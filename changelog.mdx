<Update label="2026-09-14" description="Context Repositories" tags={["feature", "improvement"]}>
## What changed

**Context Repositories**
- Connect GitHub and GitLab repositories as context sources for the Doc Agent
- The Agent reads code at a pinned commit for each run, ensuring a consistent snapshot throughout the run
- Set a default branch per connected repository
- Override the default branch for individual chats and workflows
- Branch resolution follows a priority order: merge commit from a pull request trigger, then the chat or workflow branch, then the repository's Agent default, then the repository's own default branch
- If the requested branch no longer exists, the Agent falls back to the repository's default branch

**GitLab Improvements**
- GitLab repositories now appear as a distinct connector type instead of being grouped under GitHub
- Connect GitLab repositories as context-only sources using read-only tokens
- Two connection purposes: `source` for repositories that publish documentation (requires write access) and `context` for repositories the Agent reads (requires read access)
- Nested group paths such as `group/subgroup/project` are supported
- Merge-request automations trigger only on the actual merge action, not on later updates to an already merged request

**Connector Management**
- Each provider (GitHub and GitLab) supports up to 10 connected repositories with separate limits
- Re-attaching the same repository does not use an additional connector slot
- Repository lookups are now scoped to your organization to prevent resolving same-named repositories from other organizations
</Update>

<Update label="2026-09-07" description="Latest Updates" tags={["feature", "improvement", "fix"]}>
## What changed

**Media Manager**
- Upload and manage images, video, and other files in a dedicated media library
- Access media files from a sidebar panel directly in the editor
- Drag and drop multiple files at once, including within read-only contexts
- View inline previews for PDFs and videos
- Replace existing media files while preserving page references
- Monitor storage usage with plan-based quotas and upgrade options
- Track media changes with audit logging
- Compact thumbnails in list views and search results

**Reusable Snippets**
- Create reusable `.mdx` and `.jsx` snippet files from the editor file tree
- Insert snippets into any page using the `/snippet` slash command
- Preview snippets with live JSX compilation before insertion
- Snippets are automatically included in site builds and deployments
- Snippet content is indexed and searchable alongside your pages
- Caching and dependency detection keep snippet previews fresh
- Add optional descriptions when creating snippets

**Search Analytics**
- Track search queries and reader behavior with a new analytics dashboard
- View search volume trends, event tables, and result performance reports
- Privacy-first tracking with debounced and validated events
- Access analytics via API for custom integrations

**Collaboration & Auth**
- Rename and move files across directories with full destination path support
- Role-based access control now enforced for signed-in readers with cached delivery
- Private documentation pages served from cache for authenticated readers
- OAuth redirect URI now resolves from forwarded host for reverse-proxy compatibility
- Performance improvements through per-request config and session deduplication

**Platform Fixes**
- Fixed video player preload behavior when no poster image is set
- Webhook deploys now only trigger for branch refs, not tags
- MDX cache tagging improved for deterministic revalidation
- Sidebar animation transition duration corrected
</Update>
