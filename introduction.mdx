---
title: Data Visibility & Scanning
---
_Answers to the most frequently asked questions about data visibility and scanning in ARMOR DSPM.&#x20;_

<ExpandableGroup>
  <Expandable title="Which repositories/surfaces are supported today for DSPM?" default-open="false">
    Armor Discovery currently supports the following repository types:

    **On-Premises**

    Armor Discovery currently supports on-premises file servers over the SMB (Server Message Block) network file protocol. Because SMB is widely adopted across the industry, the following vendors are supported:

    - Windows
    - Linux
    - NetApp
    - EMC Isilon
    - Nasuni

    CIFS (legacy SMB 1.0) is not supported, as the protocol is deprecated. Support for CIFS can be added to the roadmap based on customer requirements.

    **SaaS Repositories**

    Armor Discovery currently supports the following SaaS repositories:

    - Microsoft 365 - SharePoint Online, Microsoft Teams, OneDrive
    - AWS S3

    Support for the following repositories is planned for a future release: Salesforce, Google Drive, Jira, and Confluence.
  </Expandable>

  <Expandable title="Is scanning Structured data supported?" default-open="false">
    Currently it is not supported. This feature is planned on the product roadmap.
  </Expandable>

  <Expandable title="Does Seclore Armor DSPM use agents?" default-open="false">
    Seclore Armor DSPM does not use agents. It offers agentless, API-based integration for the following platforms:

    - Microsoft SharePoint
    - Microsoft Teams
    - OneDrive
    - AWS S3

    For on-premises environments, dedicated scanning options are available.
  </Expandable>

  <Expandable title="Can you discover assets across multiple regions?" default-open="false">
    Yes. Armor DSPM supports asset discovery across multiple regions. It discovers and catalogs both cloud-native and on-premises data repositories deployed across your cloud environments.
  </Expandable>

  <Expandable title="Does Armor DSPM support on-demand and scheduled discovery of assets?" default-open="false">
    Armor DSPM does not currently support on-demand or scheduled discovery. Only continuous scanning is supported at this time.
  </Expandable>

  <Expandable title="Why is scheduled scanning not supported in addition to continuous scanning, given that other vendors offer this capability?" default-open="false">
    Scheduled scanning introduces visibility gaps, leaving files undiscovered between scan intervals. It also relies on resource-intensive, point-in-time scans that can increase system load. ARMOR Discovery uses continuous, delta-driven evaluations based on file changes and metadata to provide more consistent and efficient coverage.
  </Expandable>

  <Expandable title="Can scan throttling be configured through the administrative console (GUI), or does adjusting throttling require custom development or professional services?" default-open="false">
    Throttling is handled automatically by the system. It monitors signals from the data source, such as rate-limiting errors, and dynamically backs off and retries after some time automatically.
  </Expandable>

  <Expandable title="Can the solution discover files that are actively in use (for example, a document being edited on OneDrive)? If not, does it retry after the document is closed?" default-open="false">
    Yes. The solution can discover and catalog files even when they are actively in use (for example, a document being edited in OneDrive). However, remediation actions may fail if the file remains in use for an extended period.
  </Expandable>

  <Expandable title="For Microsoft 365 discovery, can administrators target specific sites or is everything scanned?" default-open="false">
    Yes. Armor DSPM allows administrators to define the scope of scanning. The following targeting options are available:

    - A specific document library within a site
    - A particular subfolder within a library as the root for scanning

    Scanning an entire Microsoft 365 site or repository is not currently supported. Administrators must select individual document libraries to initiate scanning.

    Full-site scanning support is planned for a future release and can be prioritized based on customer requirements.
  </Expandable>

  <Expandable title="For file servers, what protocols are supported (SMB/CIFS/NAS)?" default-open="false">
    - Currently, Server Message Block (SMB) and Network-Attached Storage (NAS) are supported.
    - Common Internet File System (CIFS) could be added quickly if needed based on customer feedback (with a note CIFS is legacy).
  </Expandable>

  <Expandable title="Will local OneDrive (synced to endpoint) be supported?" default-open="false">
    Yes. Local OneDrive synced to an endpoint is supported through the Microsoft 365 data repository integration. Scanning occurs at the cloud level and does not rely on endpoint scanning.
  </Expandable>

  <Expandable title="What type of access does Seclore require to connect to a repository?" default-open="false">
    Seclore requires the following levels of access depending on the intended use:

    | Access Level | Purpose                                                                                             |
    | ------------ | --------------------------------------------------------------------------------------------------- |
    | Read         | Required for DSPM visibility only                                                                   |
    | Write        | Required for remediation actions, including Digital Asset Classification (DAC) and EDRM protection. |

    EDRM protection is planned for a future release.
  </Expandable>

  <Expandable title="Do repositories need to be organized by department, and where do Owner and Department values come from?" default-open="false">
    No. Repositories do not need to be organized by department. A single repository can span multiple teams or support cross-functional projects.

    Department is an optional free-text metadata field assigned at the repository level during onboarding.

    The following fields are manually entered as free-text in the Data Control Tower UI during repository configuration:

    | Field      | Input Method                  |
    | ---------- | ----------------------------- |
    | Owner      | Manually entered as free-text |
    | Department | Manually entered as free-text |

    Integration with Identity Providers (IdP) and Human Resource Management Systems (HRMS) to automatically populate the Owner and Department fields is planned for a future release.
  </Expandable>

  <Expandable title="How fast is scanning, how long does it take per repository, and how frequently does it run?" default-open="false">
    Armor DSPM uses a continuous, delta-driven scanning model. After the initial baseline scan, the system monitors file changes including creation, modification, and renaming and reprocesses only the affected files. The scanning cadence adapts dynamically based on available system resources.

    **Initial Scan:** For a new repository, results typically begin appearing in the catalog within a few hours, depending on the file count and available system resources.

    **Parallel Scanning:** Multiple repositories are scanned simultaneously. As a result, data from multiple repositories is discovered and becomes available in the catalog at the same time.

    **Performance and Throttling:** Armor DSPM dynamically adjusts scanning speed based on the following factors:

    | Factor                   | Behavior                                                                       |
    | ------------------------ | ------------------------------------------------------------------------------ |
    | CPU and RAM availability | Scanning speed adjusts based on available system resources                     |
    | Repository API limits    | Scanning slows down upon receiving throttling signals from the data repository |
    | Throttling               | Applied automatically to avoid impact on production systems                    |

    Formal performance benchmarking documentation and a Hardware Sizing Calculator are planned on the roadmap.
  </Expandable>

  <Expandable title="How are file changes tracked?" default-open="false">
    Armor DSPM detects and rescans changed files automatically through continuous scanning. The system uses each repository's published interfaces and change notification mechanisms to identify the following file events:

    - New files
    - Modified files
    - Renamed files

    The following are examples of supported change notification mechanisms:

    - Webhooks
    - Delta APIs

    The exact change notification mechanism varies by repository type. After the initial baseline scan, only delta files are reprocessed.
  </Expandable>

  <Expandable title="If a file extension is changed or removed, will Discovery still scan it?" default-open="false">
    Yes, the file will be scanned and treated as a new file whenever its extension changes.
  </Expandable>

  <Expandable title="Which file types are supported today?" default-open="false">
    As of March 2026, Armor DSPM supports 30+ file formats, powered by Apache Tika. The supported file types are as follows:

    | Category                      | Supported Formats                          |
    | ----------------------------- | ------------------------------------------ |
    | Microsoft Office - Word       | .doc, .docx, .docm, .rtf                   |
    | Microsoft Office - Excel      | .xls, .xlsx, .xlsm, .xlsb, .csv            |
    | Microsoft Office - PowerPoint | .ppt, .pptx, .pptm                         |
    | OpenDocument                  | .odt, .ods, .odp, .odg, .odf, .odb         |
    | PDF                           | .pdf                                       |
    | Text                          | .txt, .csv, .rtf                           |
    | Images                        | .png, .bmp, .jpeg, .jpg, .gif, .tiff, .tif |
    | Seclore Secure Email          | .smail                                     |
    | CAD                           | .dwg (metadata only)                       |

    Audio and video files are not currently supported. Support for additional file formats is planned for a future release.
  </Expandable>

  <Expandable title="How are Seclore-protected files handled?" default-open="false">
    Support for discovering content in Seclore-protected files is not available yet and this capability is planned on the roadmap.
  </Expandable>

  <Expandable title="Is Optical Character Recognition (OCR) supported?" default-open="false">
    Yes. Armor DSPM supports Optical Character Recognition (OCR). OCR extracts text from images using the following components:

    - Apache Tika
    - Tesseract (OCR component)

    The extracted text is then processed by the Large Language Model (LLM) for classification and analysis.

    OCR processing is resource-intensive and is managed independently from standard text extraction.

    Customers planning heavy OCR usage should expect additional hardware sizing requirements beyond the minimum specifications.
  </Expandable>

  <Expandable title="Does scanning reset the last accessed date on files?" default-open="false">
    The following table describes the impact of Armor DSPM scanning on file timestamp metadata:

    | Metadata Field     | Impact of Scanning          |
    | ------------------ | --------------------------- |
    | Last Accessed Date | Updated during scanning     |
    | Last Modified Time | Not updated during scanning |

    Most SaaS data repositories, such as Microsoft SharePoint, do not allow the last accessed date to be modified or reset after scanning occurs.
  </Expandable>

  <Expandable title="Does the remediation (e.g. DAC) of files reset the last accessed or last modified date on all of my files?" default-open="false">
    Yes. The remediation (e.g. DAC) of files reset the last accessed or last modified date on all of my files.
  </Expandable>

  <Expandable title="Are multilingual documents (Chinese, Hindi, Indonesian, etc.) supported?" default-open="false">
    The Armor DSPM AI engine has been validated with the following languages during QA cycles:

    - English
    - Arabic
    - Chinese

    Support for additional languages is anticipated based on the underlying Large Language Model's (LLM) multilingual capabilities. However, additional components may be required depending on the language.

    Formal performance benchmarking for non-English languages is currently in progress. Results will be made available upon completion.

    If support for a specific language is a critical requirement, provide sample files to the product team for validation before making any commitments.
  </Expandable>

  <Expandable title="How is an unsupported file treated?" default-open="false">
    Unsupported files are not excluded from discovery. They are cataloged and remain visible in the catalog with the following basic file attributes captured:

    - File size
    - Hidden status
    - Read-only status

    The following semantic attributes will be empty for unsupported files, as content cannot be extracted:

    | Semantic Attribute | Value for Unsupported Files |
    | ------------------ | --------------------------- |
    | Category           | Empty                       |
    | Data Type          | Empty                       |
    | Sensitive Info     | Empty                       |

    The exported CSV report includes a list of skipped files along with the reason for each skip.
  </Expandable>

  <Expandable title="If a file extension is changed or removed, will Armor DSPM still scan it?" default-open="false">
    Yes. Armor DSPM scans and treats the file as a new file whenever its extension changes or is removed.

    File type identification is performed by Apache Tika, which examines the internal content structure of the file rather than relying on the file extension. This ensures that the correct file type is detected regardless of extension tampering or removal.
  </Expandable>

  <Expandable title="Can Discovery read existing Microsoft sensitivity labels on files for visualization?" default-open="false">
    Currently, Seclore Discovery does not support this capability. API-based integration would be the more robust approach. However, as an initial iteration, we are considering implementing metadata reading first, and it is included in the roadmap.

    Microsoft Purview Information Protection (MPIP) label reading will be supported as part of the Additional Attributes feature. It does not require MPIP API integration. MPIP API integration is primarily needed when MPIP is used for remediation.
  </Expandable>

  <Expandable title="Where do Owner and Department values come from?" default-open="false">
    Currently, these are free-text fields set during repository configuration. There is a plan to later integrate with identity/HRMS systems to fetch this information automatically.
  </Expandable>

  <Expandable title="Are password-protected files and Seclore-protected files supported for content discovery?" default-open="false">
    The following table describes the current support status for protected file types:

    | File Type                | Discovery Support      | Content Extraction     | Catalog Visibility                     |
    | ------------------------ | ---------------------- | ---------------------- | -------------------------------------- |
    | Password-Protected Files | Not supported          | Not supported          | Visible with empty semantic attributes |
    | Seclore-Protected Files  | Planned on the roadmap | Planned on the roadmap | -                                      |

    Password-protected files are skipped by the scanner and are excluded from AI classification results, as the connector cannot access their content. However, these files remain visible in the catalog with empty semantic attributes.

    Support for scanning Seclore-protected files is planned on the roadmap.
  </Expandable>

  <Expandable title="Is there a minimum or maximum file size for AI categorization?" default-open="false">
    The following table describes the file size thresholds applied during AI categorization:

    | Threshold | File Type            | Limit            | Behavior                                                                            |
    | --------- | -------------------- | ---------------- | ----------------------------------------------------------------------------------- |
    | Minimum   | All files            | 100 characters   | Files with fewer than 100 characters of content are excluded from AI-based analysis |
    | Maximum   | Text-based files     | No hard limit    | All text-based content is processed regardless of size                              |
    | Maximum   | Image OCR processing | To be determined | A cap will be introduced due to the resource-intensive nature of OCR processing     |

    Files containing fewer than 100 characters are intentionally excluded from AI-based analysis, as AI predictions are less reliable with minimal text content. This exclusion will remain in effect until reliability for low-character files improves.

    A maximum file size cap for image OCR processing is planned for a future release.
  </Expandable>

  <Expandable title="If a discovery scan is interrupted due to a network or server failure, does it restart from the beginning or resume  afrom where it left off?" default-open="false">
    The behavior following a scan interruption depends on the scan activity type, as described in the following table:

    | Scan Activity                                         | Behavior After Interruption            |
    | ----------------------------------------------------- | -------------------------------------- |
    | Categorization of queued files                        | Resumes from the point of interruption |
    | Incremental scan (discovery of new and updated files) | Restarts from the beginning            |

    Resume support for incremental scans is planned for a future release.
  </Expandable>

  <Expandable title="Does Armor DSPM support email discovery in Microsoft Outlook?" default-open="false">
    No. Armor DSPM does not currently support email discovery in Microsoft Outlook.
  </Expandable>

  <Expandable title="Do we currently exclude files smaller than 100 characters from discovery, even though users may store sensitive information (e.g., bank account or credit card numbers) in such files?" default-open="false">
    Yes, files smaller than 100 characters are currently excluded from discovery and will be missed.
  </Expandable>

  <Expandable title="Is parallel scanning supported across repositories?" default-open="false">
    - Currently, parallel scanning is not supported.
    - Repositories are scanned one at a time, so newly added repositories remain idle until the current scan completes.
  </Expandable>

  <Expandable title="Can rescanning a file alter its data type?" default-open="false">
    Yes, data type classification can change after a rescan if the file content has been modified between scans, since LLM-based classification depends on the content at the time of scanning.
  </Expandable>

  <Expandable title="Can identical content in different file types be categorized differently?" default-open="false">
    Files with identical content but saved in different formats (e.g., TXT vs PDF) can be classified differently during data type categorization.
  </Expandable>
</ExpandableGroup>
