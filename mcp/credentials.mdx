## MCP credentials

Create and manage credentials that allow MCP clients to access your documentation projects with controlled roles and expiration.

## Access requirements

<Callout kind="alert">

Admin access is required to create, update, or revoke MCP credentials. If you do not have admin access, ask an organization admin to manage credentials for the project.

</Callout>

## Creating a credential

Create credentials from your documentation project settings.

<Steps>
  <Step title="Open your documentation project settings" icon="settings" title-type="p">

    Open the documentation project where you want to manage MCP access, then go to its settings.

  </Step>

  <Step title="Create a credential" icon="plus" title-type="p">

    Create a new credential with a name. Optionally, select the access roles and expiration date or duration.

  </Step>

  <Step title="Copy and store the token" icon="lock" title-type="p">

    Copy the returned token and store it securely. The token is shown only once when you create the credential.

  </Step>
</Steps>

<Callout kind="alert">

Save the token before closing the creation dialog. You cannot view the token again after creation. If you lose it, revoke the credential and create a new one.

</Callout>

## Credential parameters

Configure these fields when you create a credential.

<ParamField body="name" param-type="string" required="true" show-location="false">

The credential name. Use between 1 and 100 characters to identify how the credential is used.

</ParamField>

<ParamField body="accessRoles" param-type="string[]" required="false" show-location="false">

The documentation roles available to the MCP client. If you omit this field, the credential receives all roles declared in the documentation configuration. Selected roles must match roles declared in the configuration.

</ParamField>

<ParamField body="expiresAt" param-type="string | null" required="false" show-location="false">

The credential expiration. Use one of the supported relative durations: `30d`, `60d`, `90d`, `180d`, or `1y`. You can also provide an ISO timestamp or use `null` for no expiry.

</ParamField>

## Updating credential roles

Update a credential's access roles without issuing a new token. The existing token remains valid, and the new roles apply to future access using that token.

The selected roles must match roles declared in the documentation configuration.

## Revoking credentials

Revoking a credential immediately prevents MCP clients from using its token. Revocation is irreversible.

To revoke one credential, open the credential in your documentation project settings and choose the revoke action.

To revoke every credential for the project, use the revoke-all action. This invalidates all existing MCP credential tokens for the project.

<Callout kind="alert">

Revoking credentials cannot be undone. Confirm that connected MCP clients no longer need access before revoking a credential or using revoke all.

</Callout>
