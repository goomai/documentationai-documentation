## Overview

All REST API requests require an API key sent in the `Authorization` header using the Bearer token format. Generate API keys from your workspace settings, and choose a role: `viewer`, `editor`, or `admin`, when you create each key.

<Callout kind="info" collapsed="false">

Each API key carries both authentication and authorization. The key proves who is calling the API, and its assigned role determines which endpoint groups the key can access.


</Callout>

## Authentication

Send the API key as a Bearer token in the `Authorization` header.

```bash
curl https://api.documentation.ai/v1/analytics/overview \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<ParamField header="Authorization" param-type="string" required="true" deprecated="false" show-location="true">

`Bearer YOUR_API_KEY` — replace `YOUR_API_KEY` with a valid API key from your workspace settings.


</ParamField>

## Roles and permissions

API keys are assigned a role that determines which endpoints they can access.

| Role | Read endpoints | Write and deploy endpoints |
|---|---|---|
| viewer | Analytics, deployments list and status | — |
| editor | Analytics, deployments list and status | Deploy, preview deploy |
| admin | Analytics, deployments list and status | Deploy, preview deploy |

<Callout kind="info" collapsed="false">

All analytics endpoints are available to every role, including `viewer`. Deployment trigger endpoints, `POST /deploy` and `POST /deploy/preview`, require `editor` or `admin`.


</Callout>

## Security

Your API key determines which documentation data is accessible. The server always uses the documentation associated with your key, so passing a different ID in a request does not grant access to another documentation's analytics or deployments.

<Callout kind="alert" collapsed="false">

Your API key determines which documentation's data is accessible. The server always uses the documentation associated with your key — you cannot access another documentation's analytics or deployments by passing a different ID in the request.


</Callout>

## Common mistakes

<Expandable title="Why am I getting a 401?" default-open="false">

Verify that:

- The API key is valid and has not been revoked.
- The key is sent in the `Authorization` header.
- The header value includes the `Bearer` prefix and a space before the key.


</Expandable>

<Expandable title="Why am I getting a 403?" default-open="false">

This means your API key's role does not have permission for the requested endpoint. For example, a `viewer` key cannot trigger deployments. Check the role assigned to your key in workspace settings.


</Expandable>
